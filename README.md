# transport-planning

Репозиторий для решения по хакатону Транспортное планирование городов команды Клодмены :))

Графический редактор улично-дорожной сети: открывает `.osm`, позволяет визуально править граф и
сохраняет результат в `.osm`, который затем проверяется в MatSim, SUMO и Webots.

## Запуск

### В Docker, без установки окружения

```bash
docker compose up --build
```

Редактор откроется на <http://localhost:8000>. Сборка без SUMO быстрее, но без кнопки предпроверки:

```bash
docker compose build --build-arg WITH_SUMO=0
```

### Для разработки

Нужны Python 3.12 и Node.js 22.18 или новее.

Бэкенд, в первом терминале:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r req.txt
cd transport_planning
../.venv/Scripts/python manage.py migrate
../.venv/Scripts/python manage.py runserver
```

Фронтенд, во втором терминале:

```bash
cd transport_planning_frontend
npm install
npm run dev
```

Редактор откроется на <http://localhost:5173>. На стартовой странице можно выбрать свой `.osm` или
открыть пример `transport_planning/samples/example.osm`.

Для проверки файла сборкой в SUMO прямо из редактора дополнительно поставьте `eclipse-sumo`
или задайте переменную `SUMO_HOME`:

```bash
.venv/Scripts/python -m pip install eclipse-sumo
```

## Как устроено

| Часть | Где лежит | Что делает |
|---|---|---|
| Чтение и запись `.osm` | `transport_planning/editor/osm_io.py` | Накладывает правки на исходный XML, всё нетронутое остаётся как было |
| API | `transport_planning/editor/views.py` | Проекты, автосохранение правок, экспорт, проверка через `netconvert` |
| Модель графа | `transport_planning_frontend/src/core/doc.ts` | Рабочая копия, транзакции, отмена и повтор, вычисление правок |
| Операции | `transport_planning_frontend/src/core/ops.ts` | Разрез, склейка, разворот, запреты поворота и другие |
| Отрисовка | `transport_planning_frontend/src/core/scene.ts`, `src/map/` | Полосы, перекрёстки, траектории на MapLibre |
| Проверки сети | `transport_planning_frontend/src/core/validate.ts` | Ошибки связности, направлений, перекрёстков и атрибутов |
| Высоты | `transport_planning_frontend/src/core/elevation.ts` | Плавный переход по Z, запись в теги `ele` |
| Сеть симуляции | `transport_planning_frontend/src/sim/net.ts` | Полосы, манёвры, конфликты траекторий, светофоры |
| Макроуровень | `transport_planning_frontend/src/sim/macro.ts` | Пропускная способность из атрибутов, спрос, распределение потоков |
| Микроуровень | `transport_planning_frontend/src/sim/micro.ts` | Машины по модели IDM, перестроения, приоритеты, очереди |
| 3D-машины | `transport_planning_frontend/src/map/carLayer.ts` | Слой WebGL с инстансингом |

Правки хранятся отдельно от исходного файла и накладываются на него при экспорте. Новые объекты
получают положительные id выше всех существующих. Здания, маршруты и другие объекты, которые редактор
не меняет, переходят в итоговый файл без изменений.

## Симуляция

Режим «Симуляция» в верхней панели работает с тем графом, который сейчас открыт, и граф в нём не меняет.
Обе модели считают один и тот же спрос по одним и тем же манёврам, поэтому их результаты согласованы.
Это модели самого редактора: они помогают найти узкие места и ошибки графа, но не заменяют MatSim и SUMO
на сервере проверки, где итоговый результат может отличаться.

**Макроуровень** показывает загрузку всей сети за час:

- пропускная способность считается из атрибутов: тип дороги, число полос, ширина, покрытие, уклон, светофор на выезде, примыкание к главной;
- свободная скорость берётся из `maxspeed`, а если его нет, то по типу дороги;
- спрос строится из данных файла: въезды на обрывах дорог у границы по их пропускной способности, районы по площади зданий (`building`, `building:levels`) с разбивкой на жильё и рабочие места;
- поездки распределяются гравитационной моделью, потоки по сети методом последовательных приближений с функцией BPR;
- результат показан уровнями обслуживания A–F по отношению потока к пропускной способности.

Коэффициенты модели (пропускная способность полосы, поездки с м² и другие) заданы в начале `macro.ts`. Это разумные
оценки, а не калибровка по данным наблюдений за движением в Иркутске.

**Микроуровень** показывает отдельные машины в 3D:

- машины следуют друг за другом по модели IDM и перестраиваются на нужную полосу заранее;
- на перекрёстках уступают по приоритету дорог, манёвров и правилу помехи справа, не въезжают на занятый выезд;
- светофоры работают по фазам. Настоящих светофоров в данных мало, поэтому включается опция добавить их на пересечениях крупных дорог;
- пробка отмечается там, где очередь из нескольких стоящих машин держится больше 12 секунд;
- машина, простоявшая 4 минуты, снимается с дороги и учитывается в счётчике. Обычно так проявляются ошибки сети.

## Горячие клавиши

В редакторе их список открывается клавишей F1. Основные: `V` выбор, `D` дорога, `N` узел, `X` разрез,
`T` светофор, `C` переход, `B` мост, `G` тоннель, `F` развернуть, `M` склеить, `U` расклеить,
`J` объединить, `[` и `]` число полос, `Ctrl+Z` и `Ctrl+Y` отмена и повтор.
