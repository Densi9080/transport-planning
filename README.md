# transport-planning

Репозиторий для решения по хакатону Транспортное планирование городов команды Клодмены :))

Графический редактор улично-дорожной сети: открывает `.osm`, позволяет визуально править граф и
сохраняет результат в `.osm`, который затем проверяется в MatSim, SUMO и Webots.

## Запуск

### В Docker, без установки окружения

```bash
docker compose up --build
```

Редактор откроется на <http://localhost:8000>. Сборка без SUMO быстрее, но без кнопки предпроверки:

```bash
docker compose build --build-arg WITH_SUMO=0
```

### Для разработки

Нужны Python 3.12 и Node.js 22.18 или новее.

Бэкенд, в первом терминале:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r req.txt
cd transport_planning
../.venv/Scripts/python manage.py migrate
../.venv/Scripts/python manage.py runserver
```

Фронтенд, во втором терминале:

```bash
cd transport_planning_frontend
npm install
npm run dev
```

Редактор откроется на <http://localhost:5173>. На стартовой странице можно выбрать свой `.osm` или
открыть пример `transport_planning/samples/example.osm`.

Для проверки файла сборкой в SUMO прямо из редактора дополнительно поставьте `eclipse-sumo`
или задайте переменную `SUMO_HOME`:

```bash
.venv/Scripts/python -m pip install eclipse-sumo
```

## Как устроено

| Часть | Где лежит | Что делает |
|---|---|---|
| Чтение и запись `.osm` | `transport_planning/editor/osm_io.py` | Накладывает правки на исходный XML, всё нетронутое остаётся как было |
| API | `transport_planning/editor/views.py` | Проекты, автосохранение правок, экспорт, проверка через `netconvert` |
| Модель графа | `transport_planning_frontend/src/core/doc.ts` | Рабочая копия, транзакции, отмена и повтор, вычисление правок |
| Операции | `transport_planning_frontend/src/core/ops.ts` | Разрез, склейка, разворот, запреты поворота и другие |
| Отрисовка | `transport_planning_frontend/src/core/scene.ts`, `src/map/` | Полосы, перекрёстки, траектории на MapLibre |
| Проверки сети | `transport_planning_frontend/src/core/validate.ts` | Ошибки связности, направлений, перекрёстков и атрибутов |
| Высоты | `transport_planning_frontend/src/core/elevation.ts` | Плавный переход по Z, запись в теги `ele` |
| Сеть симуляции | `transport_planning_frontend/src/sim/net.ts` | Полосы, манёвры, конфликты траекторий, светофоры |
| Макроуровень | `transport_planning_frontend/src/sim/macro.ts` | Пропускная способность из атрибутов, спрос, распределение потоков |
| Микроуровень | `transport_planning_frontend/src/sim/micro.ts` | Машины по модели IDM, перестроения, приоритеты, очереди |
| 3D-машины | `transport_planning_frontend/src/map/carLayer.ts` | Слой WebGL с инстансингом |
| Фильтр | `transport_planning_frontend/src/core/filter.ts` | Скрытие объектов по атрибутам, только на карте |
| Соединения полос | `transport_planning_frontend/src/core/laneOps.ts` | Манёвры между конкретными полосами |
| Планы светофоров | `transport_planning_frontend/src/core/signals.ts` | Фазы, цикл, сигнал манёвра |
| Маршруты ОТ | `transport_planning_frontend/src/core/transit.ts`, `src/sim/transit.ts` | Линии, остановки, рейсы в моделях |

Правки хранятся отдельно от исходного файла и накладываются на него при экспорте. Новые объекты
получают положительные id выше всех существующих. Здания, маршруты и другие объекты, которые редактор
не меняет, переходят в итоговый файл без изменений.

## Интерфейс

Окно устроено как настольные программы транспортного моделирования:

- сверху меню и панель инструментов, снизу строка состояния с координатами и масштабом;
- слева окно «Сеть»: сетевые объекты с активным типом, графика и подложка, фильтр по атрибутам, линии ОТ, проверка сети;
- справа быстрый просмотр атрибутов выбранного объекта, а в режиме расчёта его параметры и результаты;
- снизу списки: отрезки, узлы, светофоры, линии, остановки, районы и корреспонденции. Их можно сортировать, искать по ним, сохранять в CSV, а часть ячеек править прямо в таблице;
- двойной щелчок по узлу открывает редактор узла: схема полос и фазы светофора.

Светлая и тёмная темы переключаются в меню «Вид».

## Полосы и светофоры

- **Линии между полосами.** На вкладке «Полосы» дороги линия переключается щелчком: пунктир, сплошная или двойная. Правило пишется в `change:lanes`, на него реагируют разметка и модель.
- **Соединения полос.** В редакторе узла можно соединить любую полосу въезда с любой полосой выезда, в том числе разрешить манёвр с «неправильной» полосы. Это пишется в `turn:lanes` и в отношение `type=connectivity`. Симуляторы читают в первую очередь `turn:lanes`, поэтому точное назначение полосы может отличаться.
- **Фазы светофора.** В редакторе узла для каждого направления видно, сколько секунд за цикл горит зелёный, жёлтый и красный, а график показывает, когда именно. Менять можно зелёный и красный направления, длину цикла, длительность и состав фаз, сдвиг, жёлтый и общий красный. Границу между фазами можно тянуть мышью, цикл при этом не меняется. Те же цифры есть в быстром просмотре узла и в панели симуляции: там виден обратный отсчёт текущего сигнала, а правка применяется на ходу, не убирая машины с дорог. План хранится в служебном теге узла `signal:plan`. Он работает в моделях редактора, а SUMO строит собственную программу светофора и этот тег не читает.

## Левая панель и полосы

- **Окно «Сеть»** устроено как список типов объектов: щелчок по названию включает вставку, значок глаза управляет видимостью, замок запрещает выбор на карте.
- **Фильтр** работает на понятных атрибутах: тип дороги, число полос, ширина, скорость. Найденное можно скрыть, оставить только его или выделить разом.
- **Полосы.** На вкладке «Полосы» видно поперечное сечение в масштабе, ширина каждой полосы пишется в `width:lanes`, общая в `width`. В свойствах дороги есть типовые профили с готовым сечением.
- **Соединения полос** (`Q`): щелчок по полосе подъезда, затем по полосе выезда; повторный щелчок снимает соединение. Система координат выбирается в строке состояния и меняет только показ: в файле всегда WGS 84.

## Организация движения

Инструменты пишут в OSM то, что могут прочитать симуляторы на сервере:

- **Участок скорости** (`S`): два клика по одной дороге вырезают участок и задают ему `maxspeed`.
- **Лежачий полицейский** (`L`): ставит на узел `traffic_calming` и делает вокруг него участок низкой скорости. Сам тег SUMO, MATSim и Webots не используют, скорость на участке читают SUMO и MATSim. Повторный клик убирает его и возвращает дорогу к прежнему виду.
- **Знаки** (`P`): `highway=give_way` или `highway=stop` с направлением на подходе к перекрёстку. Они работают в моделях редактора, а `netconvert` этих тегов в проверенной части импорта не читает.
- **Геометрия дороги**: сглаживание, дублирование (`Ctrl+D`) и параллельная дорога на заданном расстоянии.

## Общественный транспорт

Маршруты читаются из отношений `type=route` (автобус, троллейбус, трамвай, маршрутка). На вкладке «Линии ОТ» их можно смотреть на карте, менять интервал и номер, добавлять и убирать дороги и остановки, создавать новые. Интервала в исходных данных нет, поэтому по умолчанию принято 20 минут: это допущение, его стоит заменить реальным расписанием.

Автобусы едут по этим маршрутам в микромодели, прижимаются к правой полосе и стоят на остановках, а в макромодели занимают пропускную способность. Трамваи показываются на карте, но в потоке машин не участвуют.

## Симуляция

Режим «Симуляция» в верхней панели работает с тем графом, который сейчас открыт, и граф в нём не меняет.
Обе модели считают один и тот же спрос по одним и тем же манёврам, поэтому их результаты согласованы.
Это модели самого редактора: они помогают найти узкие места и ошибки графа, но не заменяют MatSim и SUMO
на сервере проверки, где итоговый результат может отличаться.

**Макроуровень** показывает загрузку всей сети за час:

- пропускная способность считается из атрибутов: тип дороги, число полос, ширина, покрытие, уклон, светофор на выезде, примыкание к главной;
- свободная скорость берётся из `maxspeed`, а если его нет, то по типу дороги;
- спрос строится из данных файла: въезды на обрывах дорог у границы по их пропускной способности, районы по площади зданий (`building`, `building:levels`) с разбивкой на жильё и рабочие места;
- поездки распределяются гравитационной моделью, потоки по сети методом последовательных приближений с функцией BPR;
- результат показан уровнями обслуживания A–F по отношению потока к пропускной способности.

Коэффициенты модели (пропускная способность полосы, поездки с м² и другие) заданы в начале `macro.ts`. Это разумные
оценки, а не калибровка по данным наблюдений за движением в Иркутске.

**Микроуровень** показывает отдельные машины в 3D:

- машины следуют друг за другом по модели IDM и перестраиваются на нужную полосу заранее;
- перед кривой машина сбрасывает скорость, траектории скругляются, а кузов разворачивается за передней частью как у настоящей машины;
- водители бывают спокойные, обычные и лихачи, их доли настраиваются. Лихачи превышают скорость, держат малую дистанцию, подрезают, пересекают сплошную, проскакивают на красный и поворачивают не из своей полосы. Вероятности нарушений заданы в начале `micro.ts`: это оценки, а не статистика;
- на перекрёстках уступают по приоритету дорог, манёвров и правилу помехи справа, не въезжают на занятый выезд;
- светофоры работают по фазам заданного плана. Настоящих светофоров в данных мало, поэтому включается опция добавить их на пересечениях крупных дорог;
- пробка отмечается там, где очередь из нескольких стоящих машин держится больше 12 секунд;
- машина, простоявшая 4 минуты, снимается с дороги и учитывается в счётчике. Обычно так проявляются ошибки сети.

## Помощник

Вкладка «Помощник» справа: чат, который сам вызывает функции редактора. Он ищет объекты, запускает макромодель, смотрит, кто едет по дороге, проверяет варианты пробным расчётом и управляет картой. Числа он берёт из расчётов редактора.

Граф помощник сам не меняет: правки появляются карточкой, подсвечиваются на карте, применяются кнопкой одним шагом и отменяются через `Ctrl+Z`. Набор операций закрытый: удалять дороги и узлы помощник не может.

Подключается любой сервис, совместимый с OpenAI API. Адрес, модель и ключ задаются отдельно в окне «Помощник → Подключение к модели» или через переменные окружения:

| Переменная | Что задаёт |
|---|---|
| `LLM_BASE_URL` | Адрес сервиса, обычно заканчивается на `/v1` |
| `LLM_MODEL` | Название модели |
| `LLM_API_KEY` | Ключ доступа, для локальных серверов обычно не нужен |
| `LLM_SETTINGS_LOCKED` | `1` запрещает менять подключение из браузера |

Значения из окна важнее переменных окружения. При `LLM_SETTINGS_LOCKED=1` работают только переменные.

**Облако:**

```bash
LLM_BASE_URL=https://api.openai.com/v1 LLM_MODEL=название-модели LLM_API_KEY=ключ docker compose up --build
```

**Локально:** запустите сервер модели на этом же компьютере, например Ollama (`http://localhost:11434/v1`) или LM Studio (`http://localhost:1234/v1`). Внутри Docker вместо `localhost` используйте `host.docker.internal`. Модель должна поддерживать вызов функций (function calling), иначе помощник не сможет запускать расчёты.

Что важно при размещении:

- ключ хранится на сервере и в браузер не возвращается, но в окне он лежит в базе в открытом виде. На общем сервере задавайте его через переменные окружения;
- входа по логину в редакторе нет: любой, кто открыл его по сети, сможет тратить ваш ключ. Для доступа не только с этого компьютера включите `LLM_SETTINGS_LOCKED=1` и закройте приложение авторизацией на прокси;
- при облачном подключении вопросы, атрибуты дорог и результаты расчётов уходят в этот сервис. При локальном они остаются на вашем компьютере.

## Горячие клавиши

В редакторе их список открывается клавишей F1. Основные: `V` выбор, `D` дорога, `N` узел, `X` разрез,
`T` светофор, `C` переход, `S` участок скорости, `L` лежачий полицейский, `P` знак, `B` мост, `G` тоннель, `F` развернуть, `M` склеить, `U` расклеить,
`J` объединить, `[` и `]` число полос, `Ctrl+Z` и `Ctrl+Y` отмена и повтор.

## Работа с сетью

Окно «Сеть» слева содержит типы объектов: узлы, отрезки, повороты, пункты и зоны остановок, остановки, маршруты, решения о желаемой скорости, зоны снижения скорости, знаки стоп, правила приоритета, светофоры, детекторы и входящие потоки. Щелчок по строке делает тип активным.

Режимы на верхней панели: «Вставка» создаёт объекты активного типа, «Редактирование» выбирает и двигает их, «Выделение» отбирает их рамкой. Клавиша Insert переключает вставку и редактирование. Инструменты находятся внизу по центру, консоль ошибок и журнал расчёта открывает клавиша Ё.

Объекты без места в OSM (детекторы, входящие потоки, правила приоритета, зоны снижения скорости, решения о желаемой скорости) записываются в `.osm` отдельными узлами вне дорог с тегами `tp:*`. На сеть SUMO они не влияют.

Кнопка «Расчёт загрузки» запускает настоящий SUMO: случайные поездки по правилам `randomTrips.py` и входящие потоки из редактора. Результат показывается на карте по полосам.
